# AVR128DB28 behavior

Microchip **AVR128DB28** (AVR DB family). Retr01 uses **three** SPDIP parts at **24 MHz** internal HFOSC:

| Instance | Ref | Job |
| --- | --- | --- |
| **MCU-M** | soft CPU I/O | Soft `$7Fxx`, SPI master, cart I2C, machine EEPROM, `CPU_RDY` |
| **MCU-S1** | video helper | OAM apply, VBlank sprite field, HBlank BG0, field SRAM ALE/`/WE` |
| **MCU-S2** | pads + audio | Arcade/TRS pads, APU mailbox, PWM audio |

Same pinout and peripherals. Different firmware images. Entity **behavior** stays on the 6502. See `../hardware.md` for the role diagram and PORT freeze.

**Package:** AVR128DB28-I/SP, 28-pin **SPDIP**, 5 V. **UPDI** = pin **19** (not PF6).

---

## 1. Inputs (what pins can sense)

### Power pins

| Pin | Name | Role |
| --- | --- | --- |
| 6 | VDDIO2 | I/O supply for Port C (MVIO). Retr01 ties to **VDD** |
| 14 | AVDD | Analog supply. On AVR DB, **internally tied to VDD** (not a separate rail to manage) |
| 15, 21 | GND | Ground |
| 20 | VDD | Main digital supply (**5 V**) |

### GPIO / special inputs (28-pin SPDIP)

Almost every port pin can be configured as digital **IN**. Many also support analog (ADC/AC) except **PF6** (digital only) and **UPDI** (program/debug).

| Pins | Names | Domain | Can sense |
| --- | --- | --- | --- |
| 1 | PA7 | VDD | Digital IN, analog |
| 2-5 | PC0-PC3 | VDDIO2 | Digital IN, analog (SPI master pins on M) |
| 7-13 | PD1-PD7 | AVDD(=VDD) | Digital IN, analog (SPI slave on S1/S2 uses PD4-PD7) |
| 16-17 | PF0, PF1 | AVDD(=VDD) | Digital IN, analog. Also XTAL32K1/2 if used |
| 18 | PF6 | VDD | Digital IN only (often reset-capable, input-oriented) |
| 19 | UPDI | VDD | Program / debug stream |
| 22-23 | PA0, PA1 | VDD | Digital IN, analog. Also XTALHF1/2 if used |
| 24-28 | PA2-PA6 | VDD | Digital IN, analog (M: TWI on PA2/PA3, CPU D bits, etc.) |

There is **no PD0** on the 28-pin part (Port D is **PD7:1**).

### What each Retr01 instance listens to

| Instance | Typical inputs |
| --- | --- |
| **MCU-M** | CPU D[7:0] (sampled/driven as IO), `SEL_SOFT0/1/2`, `CPU_A_SAMPLE`, `VBL`, `S1_RDY`, SPI MISO from slaves, TWI from cart EEPROM |
| **MCU-S1** | SPI slave (MOSI/SCK/`/SS`), optional status back to M |
| **MCU-S2** | Arcade microswitch GPIOs, TRS `PAD_DATA` (OD UART), SPI slave from M |

Exact net names: `../hardware.md` pin freeze tables.

## 2. Process (what happens inside)

### On-chip resources

| Resource | Size / count (28-pin) |
| --- | --- |
| Flash | 128 KB (firmware) |
| SRAM | 16 KB |
| EEPROM | **512 B** (machine settings on **MCU-M** via `$7F70-$7F72`) |
| User row | 32 B |
| CPU | AVR core + hardware multiplier, up to **24 MHz** |
| Clocks | Internal **OSCHF** (Retr01 baseline 24 MHz). Optional HF / 32 kHz crystals on PA0/1, PF0/1 |
| Digital | USART x3, SPI x2, TWI x1, TCA/TCB/TCD, CCL, Event System, WDT, CRCSCAN |
| Analog | ADC, DAC, AC x3, op-amps (board may leave unused) |

Not megaAVR source-compatible (`DDRx` / classic `TCCR*` differ). Toolchain target: `avr128db28`.

### Per-instance processing

| Instance | Inside the chip |
| --- | --- |
| **MCU-M** | Decode soft selects + latched A[7:0]. Serve `$7Fxx` reads/writes on D. SPI master mailboxes to S1/S2. TWI master for cart 24C64. On-chip EEPROM program/read. Assert **CPU_RDY** while slow ops run |
| **MCU-S1** | Accept OAM block over SPI. In **VBlank**, rasterize the full sprite field into field SRAM (one pass, no sprite line ping-pong). In **HBlank only**, fill the next BG0 ping-pong line. Drive AD + ALE/`/WE` toward 74HC573 + field AS6C62256 |
| **MCU-S2** | Sample pads (GPIO and/or OD UART poll). Hold APU register file from SPI. Generate **PWM** audio (TCA WO1 on PF1) |

Shared rule: keep SPI payloads small and frame-bounded. OAM SPI only in **early VBlank** or when **`S1_RDY`** is ready. Never in HBlank. Missed VBlank on S1 means sprite glitches. Long RDY on M stalls the 6502. Bound every RDY hold with a timeout.

### Boot and bus hygiene (locked)

| Rule | Detail |
| --- | --- |
| After reset | Shared bus pins **hi-Z** / inputs until handshake (VBL seen, enables sane) |
| Soft `$7Fxx` | Hard real-time path. Use **`CPU_RDY`** if the PHI2 window is too tight |
| `CPU_RDY` | Open-drain only + board pull-up |
| SPI `/SS` | Exactly one slave selected. Idle both high |
| Field AD | Hi-Z outside owned ALE/`/WE` windows |
| Async inputs | Two-flop (or event) sync for `VBL`, `SEL_SOFT*`, and similar |

See `../ic-comms-risks.md`.

### PORTMUX locks (Retr01)

| Function | Pins |
| --- | --- |
| M TWI0 (cart I2C) | PA2 SDA, PA3 SCL |
| M SPI1 master | PC0 MOSI, PC1 MISO, PC2 SCK, PC3 `/SS_S1`, PD5 `/SS_S2` |
| S1/S2 SPI1 slave ALT1 | PD4 MOSI, PD5 MISO, PD6 SCK, PD7 `/SS` |
| S2 pad UART | PF0 OD |
| S2 audio PWM | PF1 |

## 3. Outputs (what pins can drive)

Any GPIO configured as OUT can drive **H** or **L** (push-pull) or open-drain where firmware sets that mode (pad UART). UPDI is a special single-wire debug I/O during programming.

| Instance | Typical outputs |
| --- | --- |
| **MCU-M** | Drive CPU D when soft read. `/SS_S1`, `/SS_S2`, SPI MOSI/SCK. TWI OD. **CPU_RDY** OD low while busy |
| **MCU-S1** | AD[7:0], A[14:8], **ALE**, `/WE`, SPI MISO, `S1_RDY` |
| **MCU-S2** | `PAD_DATA` OD, **AUDIO_PWM**, SPI MISO, optional status GPIOs |

### Three chips on the netlist

Register the **same part string** (`"AVR128DB28"`) three times with different refdes (`"MCU_M"`, `"MCU_S1"`, `"MCU_S2"`). Behavior differences are firmware / `tick` impl, not pinout.

```text
CPU D/A/RWB -----> MCU-M  --SPI-->  MCU-S1 ----AD/ALE/WE----> field SRAM
                      |               ^
                      +-----SPI----> MCU-S2 ----PWM----> audio
                                      |
                                   pads in
```

## Sim notes

- Start with GPIO + SPI + RDY stubs per role. Grow field timing on S1 against VBlank/HBlank nets from the beam PLDs.
- Pin names should match the table (`"PA0"`, `"UPDI"`, `"VDD"`, ...) so islands stay portable.
- MVIO: model VDDIO2 as tied to VDD unless a future board revision splits rails.
- Do not put game AI in these models. That belongs to the W65C02S PRG path.
