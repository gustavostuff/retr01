# AVR128DB28 behavior

Microchip **AVR128DB28** (AVR DB family). Retr01 uses **three** of them at **24 MHz** as MCU-M, MCU-S1, and MCU-S2.

**Board roles / pin freeze:** `../hardware.md`.

## What it is

| Topic | Spec |
| --- | --- |
| CPU | AVR CPU with hardware multiplier, up to **24 MHz** |
| Flash / SRAM / EEPROM | **128 KB** / **16 KB** / **512 B** |
| User row | 32 B |
| Package on Retr01 | **AVR128DB28-I/SP** (28-pin **SPDIP**), industrial temp |
| GPIO (28-pin) | **22** usable lines: `PA[7:0]`, `PC[3:0]`, `PD[7:1]`, `PF[6,1,0]` (PF6/RESET is input-only as noted in the DS) |
| Debug / program | **UPDI** (dedicated pin on this family, pin **19** on the board freeze) |
| Supply | **1.8-5.5 V**. Retr01 runs **5 V**. **VDDIO2** tied to VDD (single-supply style) |

Peripherals on the 28-pin part (family table): USART x3, SPI x2, TWI/I2C x1 (master+slave capable on different pins per DS notes), TCA x1, TCB x3, TCD x1, RTC, DAC, ADC, AC x3, CCL, Event System, WDT, CRCSCAN.

Internal **OSCHF** high-precision oscillator supports selectable rates up to **24 MHz** (with auto-tuning). Retr01 clocks each AVR from that internal HFOSC at 24 MHz unless a later bring-up forces an external clock.

## Three jobs on Retr01

Same silicon, three firmwares:

| Instance | Owns | Heavy peripherals |
| --- | --- | --- |
| **MCU-M** | Soft `$7Fxx`, OAM/APU mailboxes, cart **24C64** I2C, machine EEPROM **512 B**, `CPU_RDY`, SPI master to S1/S2 | TWI0, SPI1 master, GPIO on CPU D and SEL lines |
| **MCU-S1** | OAM apply, VBlank sprite field, HBlank BG0 line, field SRAM via AD + HC573 | SPI slave, GPIO address/data to field RAM, ALE/`/WE` |
| **MCU-S2** | Pads `$7F60`/`$7F61`, APU mailbox `$7F40-$7F5F`, audio PWM | SPI slave, TCA PWM on **PF1**, USART OD pad bus on **PF0**, pad GPIOs |

Entity **behavior** is not an AVR job. Definitions are world data. Behavior is 6502 PRG. AVRs move pixels, pads, audio, and slow I/O.

## Pin freeze (shared rules)

From `../hardware.md` (must stay consistent with PORTMUX choices in firmware):

| Lock | Value |
| --- | --- |
| Cart I2C (M) | TWI0 DEFAULT **PA2/PA3** |
| SPI master (M) | SPI1 DEFAULT PC0 MOSI, PC1 MISO, PC2 SCK, PC3 `/SS_S1`, PD5 `/SS_S2` |
| SPI slave (S1/S2) | SPI1 ALT1 PD4 MOSI, PD5 MISO, PD6 SCK, PD7 `/SS` |
| Audio (S2) | TCA0 WO1 **PF1** (on-chip DAC on PD6 left unused) |
| Pad UART (S2) | USART2 open-drain on **PF0** |
| Field (S1) | AD[7:0] + ALE -> 74HC573. A[14:8] direct. S1 drives ALE + `/WE` only |

Three 1x3 UPDI headers (UPDI / VCC / GND), one per AVR.

## Timing behavior that matters

| Topic | Expectation |
| --- | --- |
| Soft `$7Fxx` on M | SEL_SOFT* edges + latched CPU A[7:0] (`CPU_A_SAMPLE`). M presents or captures D[7:0] in time for the 6502 cycle. Stretch with **RDY** when the reply needs I2C or EEPROM time |
| SPI M -> S1 | OAM block after CPU writes `$7F20`/`$7F21`. S1 must finish field work in **VBlank** (sprite plane) and **HBlank** (BG0 line) budgets |
| SPI M -> S2 | APU register forwards. Pad state is sampled on S2 and readable to the CPU through M |
| Machine EEPROM | On-chip **512 B**. Mailbox `$7F70-$7F72`. Program time is milliseconds. Hold `CPU_RDY` until done |
| Cart EEPROM | External 24C64 via M TWI. Mailbox `$7F22-$7F24`. Same RDY stall model |

## Power / MVIO

**VDDIO2** can run a second I/O voltage (port C / MVIO). Retr01 ties **VDDIO2 = VDD** so all GPIO are 5 V single supply. Treat MVIO as unused dual-rail mode.

## Firmware split (behavioral)

| Concern | Where it runs |
| --- | --- |
| Decode soft selects, RDY policy, I2C, SPI master | MCU-M firmware |
| Sprite field compositor work, BG0 line prep | MCU-S1 firmware |
| Debounce / pad UART / PWM ISR | MCU-S2 firmware |
| Game rules, entity AI | W65C02 PRG only |

Keep SPI messages small and bounded per frame. If S1 misses VBlank, sprites glitch. If M holds RDY too long, audio/pad cadence suffers.
